# Ianvs ACP 应用设计评审

日期：2026-06-05

## 审查范围

本次评审覆盖 Ianvs ACP Flutter 客户端的主工作台、会话创建、会话恢复、代理菜单、会话设置、能力查看、权限请求、启动错误和窄窗口状态。

用户目标：快速选择或恢复一个 ACP 会话，读懂代理输出，必要时调整会话设置，并安全处理权限请求。

无障碍目标：核心操作清楚、状态可感知、键鼠操作目标足够大，窗口变窄时内容不能互相挤压或丢失。

## 取证方式

截图保存在 `docs/design-audit-2026-06-05/screenshots/`。

先尝试用 Flutter Web 运行审查入口，但项目包含桌面侧 stdio/MCP 依赖，Web 编译失败。因此改用 Flutter widget 截图测试生成画面。截图使用真实组件和假客户端数据，但不是完整 macOS 原生窗口截图。

截图限制：

- 少量 Material 图标在测试环境中显示为方块，不作为产品问题判断。
- 少量弹窗标题粗体在测试截图中显示异常，报告判断以主体布局、层级和代码文案为准。
- 截图不能证明完整 WCAG 符合情况，键盘焦点、读屏顺序、真实窗口缩放还需要在 macOS 运行态继续验证。

## 截图步骤

1. `01-empty-desktop.png`：空状态。整体健康，中心任务入口清楚，但同一动作在顶部、左栏、中心重复出现。
2. `02-new-session-dialog.png`：新会话弹窗。基本健康，工作目录输入明确，但弹窗标题和路径建议的主次关系还可以更清楚。
3. `03-active-conversation.png`：活跃会话。中等健康，消息、工具、计划、命令卡片完整，但视觉权重接近，用户需要多扫几眼才知道下一步。
4. `04-agent-menu.png`：代理菜单。中等健康，功能入口集中，但普通切换项、配置项、登录、扩展请求和退出混在一个菜单里。
5. `05-resume-dialog.png`：恢复会话弹窗。健康，搜索、项目、会话、预览齐全，适合多项目用户。
6. `06-session-settings-dialog.png`：会话设置弹窗。健康，模型、推理强度、审批模式组织清楚，操作区偏多但还可控。
7. `07-capabilities-dialog.png`：能力查看弹窗。已加入能力摘要，用户可以先看“就绪”和“需注意”，再看下面的细节。
8. `08-permission-request.png`：权限请求。权限卡片仍然醒目，但输入框外层已恢复普通样式，视觉压力比原始版本更轻。
9. `09-startup-error.png`：启动错误。健康，错误横幅克制、可读，没有遮挡主要界面。
10. `10-narrow-width.png`：窄窗口。已改成单栏时间线，会话栏收起，计划项可以换行，不再触发原先的 RenderFlex 溢出。

## 本轮已实施优化

- 窄窗口：`AppShell` 在小于约 `700px` 的主内容宽度下隐藏会话侧栏，时间线独占空间；计划项和消息标题允许换行。
- 顶部动作：`Reconnect` 不再作为常驻动作，只在断开或错误状态可用时出现。
- 状态栏：窄宽度下隐藏设置、能力查看和主题等次要图标，保留会话与连接状态信息。
- 权限态：权限请求保留独立高亮卡片，输入框外层恢复普通边框和阴影，降低底部区域的告警面积。
- 能力弹窗：顶部增加 `Capability summary`，把关键能力分成 `Ready now` 和 `Needs attention`。
- 回归验证：新增窄窗口主界面、窄计划项、状态栏响应式、能力摘要和权限输入区样式测试，并更新截图回归基线。

## 优点

- 主结构稳定：顶部代理状态、左侧会话、中央时间线、底部输入、状态栏的分区明确。
- 空状态友好：没有会话时给出清楚的启动动作，插画轻但不抢内容。
- 会话恢复流程完整：项目搜索、会话搜索、预览和加载动作都在同一弹窗中完成。
- 权限请求足够显眼：危险或需要确认的状态不会被普通聊天内容淹没。
- 能力和设置弹窗信息扎实：协议能力、模型、推理强度、审批模式都能被用户检查。

## 主要问题

### 1. 窄窗口会把主界面挤坏

原始证据：`10-narrow-width.png` 曾记录 `RenderFlex overflowed`，位置在 `lib/ui/components/chat_timeline.dart:1421` 附近。

原始原因：主工作区使用横向 `Row`，左侧 `SessionSidebar` 固定 `244px`，中间时间线只剩很小宽度。计划项行使用横向图标、文本、优先级标签组合，空间不足时优先级标签继续占宽。

影响：用户把桌面窗口缩窄、分屏或用小屏设备时，聊天内容不可读，计划卡片和命令卡片会溢出。

本轮处理：小宽度下先采用单栏模式，左侧会话栏收起；计划项在窄宽度下把优先级标签换到下一行；时间线消息标题行允许换行。

### 2. 顶部动作和菜单层级偏混

证据：`03-active-conversation.png` 和 `04-agent-menu.png`。

顶部同时放了 `Agents`、`Resume`、`Reconnect`、`New Session`。其中 `New Session` 是主动作，`Resume` 是次主动作，`Reconnect` 更像修复动作，`Agents` 又包含配置、协议、认证、扩展请求和退出。

影响：新用户会先看到一排相似按钮，不容易判断应该先开始会话、恢复会话，还是配置代理。

本轮处理：`Reconnect` 只在连接异常或断开时出现。`New Session`、`Resume` 和代理菜单分组仍可继续细化。

### 3. 状态栏信息太挤，操作目标偏小

证据：`03-active-conversation.png`、`09-startup-error.png`、`10-narrow-width.png`。代码里状态栏高度是 `30px`，并使用横向滚动承载路径、会话 id、模型、状态、延迟和多个图标，见 `lib/ui/components/status_bar.dart:21` 到 `105`。

影响：桌面宽屏下勉强可读，窄一点就需要横向滚动。多个小图标既是状态又是入口，鼠标目标小，键盘焦点和读屏名称需要额外验证。

本轮处理：窄宽度下先隐藏设置、能力查看和主题图标，保留状态信息。后续仍建议把检查类入口移到更明确的工具位置。

### 4. 权限请求过于压迫输入区

证据：`08-permission-request.png`。权限请求进入后，底部输入区变成大面积橙色边框和阴影，权限卡片、输入框和底部配置芯片都被同一个警告状态包住。

影响：风险很明确，这是优点。但用户此时需要做的只有读请求并允许或拒绝，周围的输入框、模型选择、审批模式芯片会增加噪音。

本轮处理：权限请求卡片仍作为主要决策区，输入框外层恢复普通样式，减少整个底栏都进入告警态的感觉。

### 5. 时间线卡片的主次关系还不够强

证据：`03-active-conversation.png`。用户消息、助手消息、工具卡片、计划卡片、命令卡片都很完整，但卡片边框、标题、标签、芯片数量较多，视觉重量接近。

影响：当对话变长时，用户需要花时间区分“最终回答、正在执行的计划、已完成工具、可用命令”。

建议：把时间线内容分成三类显示：对话正文、执行过程、辅助信息。执行过程可以默认折叠为一行摘要，计划卡片突出当前进行项，命令列表可移到输入区的命令提示中，避免长期占据时间线。

### 6. 能力查看弹窗信息完整但缺少结论

证据：`07-capabilities-dialog.png`。

弹窗列出大量 supported/off 芯片，适合开发者查细节，但普通用户更想知道“当前代理能不能做我想做的事”。

本轮处理：顶部已加入能力摘要，把关键能力分成 `Ready now` 和 `Needs attention`，原始能力细节保留下方继续查看。

## 无障碍风险

- 多处按钮和图标使用紧凑视觉密度，真实命中面积需要检查。代码主题设置了 `VisualDensity.compact` 和 `MaterialTapTargetSize.shrinkWrap`，小目标对手部不稳的用户不友好。
- 原始窄窗口文字竖排和溢出风险已缓解，但真实 macOS 小窗口仍需要继续验证。
- 仅靠颜色区分状态的地方较多，例如紫色、绿色、橙色芯片。需要确认文字标签和读屏语义是否完整。
- 弹窗遮罩清楚，但需要验证键盘焦点是否进入弹窗、关闭后是否返回触发按钮。

## 建议优先级

1. 继续优化时间线层级：执行过程默认摘要化，正文和最终结果更突出。
2. 继续简化顶部动作：`Reconnect` 已按状态出现，后续可把代理菜单按切换、检查、账户操作分组。
3. 深化状态栏整理：窄宽度已隐藏次要图标，后续可把检查类入口移到更明确的工具位置。
4. 验证真实 macOS 小窗口：确认标题栏、安全区、最小窗口尺寸和系统字体下仍不溢出。
5. 做键盘和读屏检查：覆盖新会话、恢复、能力查看、设置和权限处理。
6. 用真实长内容压测：长路径、长会话标题、长工具名、长模型名再跑一轮截图。

## 可继续验证

- 在真实 macOS 窗口中验证最小窗口尺寸、标题栏、安全区和系统字体。
- 使用键盘完整走一遍：新会话、恢复、打开设置、处理权限、关闭弹窗。
- 用读屏检查按钮名称，尤其是图标按钮、状态栏图标和权限决策按钮。
- 用真实长路径、长会话标题、长工具名、长模型名再跑一轮截图。
